# AI 编码通用规则

## 一、基本原则

1. AI 可以辅助编码，但不能绕过 Git、校验、diff 审查和人工确认。
2. 不允许 AI 直接在 main/master 分支上编码。
3. 不允许 AI 自动提交、自动推送、自动合并。
4. 每个 AI 编码任务必须有明确 TASK 文件。
5. 每个 AI 子任务必须使用短生命周期 ai/* 分支。
6. 每个 AI 子任务建议使用独立 git worktree。
7. 每个 AI 子任务只解决一个明确问题。
8. 不允许 AI 顺手重构无关代码。
9. 不允许 AI 引入新依赖，除非任务明确允许。
10. 不允许 AI 修改高风险文件，除非任务明确允许。

## 二、默认禁止修改

除非 TASK 文件明确允许，否则默认禁止修改：

- package.json
- pnpm-lock.yaml
- yarn.lock
- package-lock.json
- .env
- .env.*
- 构建配置
- 部署配置
- CI/CD 配置
- 权限控制文件
- 路由核心文件
- 全局状态文件
- 公共 API 客户端
- 与当前任务无关的业务模块

## 三、AI 执行要求

AI 执行任务时必须遵守：

1. 先阅读 TASK 文件。
2. 只修改允许范围内的文件。
3. 不修改禁止范围内的文件。
4. 不做额外重构。
5. 不新增依赖。
6. 不自动提交。
7. 完成后输出修改文件清单、主要改动说明、风险点、验证方式和回滚建议。

## 四、提交前检查

提交前必须检查：

git status
git diff
git diff --stat

如果已经暂存，还要检查：

git diff --cached

## 五、主干规则

main/master 必须保持稳定。

任何 AI 生成代码进入 main/master 前，必须经过：

1. diff 审查。
2. 校验命令。
3. integration 分支集成验证。
4. 人工确认。
